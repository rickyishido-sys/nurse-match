## 1. 現在の Build は iPhone 専用か？

### 結論（この段階）

**アップロード済み Build が `TARGETED_DEVICE_FAMILY=1`（iPhone専用）であることは、現環境からは確定できません。**

### 根拠

| 確認先 | 結果 |
|--------|------|
| リポジトリ内の `ios/` Xcode プロジェクト | **未コミット**（`native/hanakai/.gitignore` で除外）。ASC に載せたバイナリの設定はここにはない |
| Capacitor 8 が生成する雛形（`npx cap add ios`） | `TARGETED_DEVICE_FAMILY = "1,2"`（**iPhone + iPad**） |
| `docs/store-submission/store-metadata.md` | 配信デバイス表記が「iPhone / iPad」 |
| App Store Connect API / 審査用認証情報 | この環境に未設定 |

### 次に必要な確認（人間 / ASC）

App Store Connect → 該当アプリ → 最新アップロード Build → 対応デバイスを確認:

- **iPhone のみ** → iPhone 6.9" クラスのスクショだけで足りる（下記サイズ）
- **Universal（iPhone + iPad）** → **iPad 13" スクショも必須**（2064×2752 または 2048×2732）

> 推測で iPhone 専用と断定しないこと。雛形デフォルトは `"1,2"`。

## 2. Apple 公式の最新スクリーンショットサイズ

出典: Apple Developer — App Store Connect Help — Screenshot specifications（2026-08-11 取得）

### 重要: 「6.7インチ」単独枠は現行仕様にない

App Store Connect の iPhone 主枠は **6.9" Display**。  
ここに、従来「6.7インチ」と呼ばれていた解像度（1290×2796）も含まれる。

### iPhone — 6.9" Display（必須クラス）

対象例: iPhone Air / 17 Pro Max / 16 Pro Max / 16 Plus / 15 Pro Max / 15 Plus / 14 Pro Max など

| 向き | 受理される pixel サイズ |
|------|-------------------------|
| Portrait | **1260 × 2736** / **1290 × 2796** / **1320 × 2868** |
| Landscape | 上記の縦横入れ替え |

制約:

- 形式: `.jpeg` / `.jpg` / `.png`
- **アルファチャンネル・透過不可**
- 枚数: 1〜10

### フォールバック

- 6.9" を出さない場合のみ、6.5" が必須になる
- 6.9" を出せば、小さいクラスはスケール利用可

### この案件での固定サイズ（提案）

| 用途 | 固定サイズ | 理由 |
|------|------------|------|
| **主成果物（推奨）** | **1320 × 2868**（portrait） | 6.9" クラス最大解像度。ASC にそのままアップロード可能 |
| 互換出力（任意） | 1290 × 2796 | 旧「6.7インチ」相当。6.9" クラスでも受理される |

**iPhone 専用が確認できた場合:** 上記 iPhone セットのみ作る。  
**iPad 対応だった場合:** 追加で 13" Display（2064×2752 または 2048×2732）が必要。

## 4. 推奨6枚構成（ストーリー）

一本の流れ: **出会う → 探す → 知る → 申し込む → 伝わる → 主催する**

| # | 画面 | パス / フレーム | 選定理由 |
|---|------|-----------------|----------|
| 1 | ホーム | `/home`（ログイン後） | 現行ボトムナビ起点。「リアルで出会う」価値提案が一言で出る |
| 2 | イベント一覧 | `/events` | カテゴリ（花・カフェ・散歩等）と週替わり体験が一覧で伝わる |
| 3 | イベント詳細 | `/events/a27f5be8-…` 上部〜詳細 | 実世界イベント（日時・場所・少人数・本人確認）が中心 |
| 4 | 参加申請 | 同詳細 `#event-apply`（参加理由フォーム） | 「想いを添えて申請」が現行 UI そのもの。**申請送信・課金はしない** |
| 5 | プロフィール | `/my-profile` | 人柄・興味・信頼バッジ。マッチングUIではない |
| 6 | イベント作成 | `/events/create` | 「誰でも主催できる」。コミュニティ空状態より訴求力が高い |

### #6 の代替

| 代替 | 使う条件 |
|------|----------|
| `/connections`（参加記録あり） | 審査アカウントに承認済み参加があり、空状態でないとき |
| ランディング `/` | ログイン後ホームが個人情報過多で使えない場合のフォールバック（優先度低） |

### デザイン方針（撮影・仕上げ）

- 実画面主役。過度な広告フレーム・ステッカー・バッジ重ねなし
- キャプションは短文1行程度。文字量を増やしすぎない
- 色調: 現行ブランド（緑 `#1f5d4f` / 金 `#b8956a` / ライト背景）
- 「マッチ」「スワイプ」「出会い系」表現は使わない
- ステータスバーはクリーン（満充電・時刻固定など）推奨
